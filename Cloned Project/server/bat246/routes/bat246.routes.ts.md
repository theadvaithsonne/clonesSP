# `server/bat246/routes/bat246.routes.ts`

> The main BAT246 Express router. It serves board reads and actions, distributor qualification progress, membership, invites, approval and placement of distributors onto boards, POD placement, notifications and card history.

**Kind:** BAT246 game module (backend) — Express router · **Lines:** 911 · **Mounted at:** `/bat246` (browser: `/backend/bat246`)

## Purpose
This is the main HTTP entry point for the BAT246 board game, the "baseball diamond" game with Home Plate, 3rd Base, 2nd Base A/B, four 1st Base slots, eight AT BAT slots, a dugout and PODs. Many routes are thin wrappers around `bat246.controller.ts`. Others are written inline, either because they need permission checks or because they combine several models: distributor progress self-healing, claim-invite, approve, POD placement, Board Entry invites and card history. The more specialised BAT246 features have their own routers, mounted at sub-paths in `server/app.ts`: Lost Money, Permissions, Layaway / B2 Coins, Snap Back Loans and Profile.

## How it works

### Permission helpers (L22-L66)
- `hasDashboardAccess(userId)`: true if the user's `Bat246Player` holds Home Plate, 3rd Base, 2nd Base A/B or any 1st Base slot on any board. AT BAT does not count.
- `isFirstBasePlayer(userId)`: true if the player holds any 1st Base slot. This lets them approve and place distributors.
- `getMySalesCredits(userId)`: for a 1st Base player, returns the slot's Green Card count `salesCredits` (0-2), how many AT BAT slots on that board are filled, and the slot's `cardType`. Every value is `null` for anyone who is not on 1st Base. This drives the "Gold Approve" mode described below.
- `Bat246Board` is loaded with a dynamic `import()` inside handlers. The same happens for `Invoice`, `Bat246OfficeInvite`, `env`, `mailer` and several service functions. This is most likely to avoid circular imports.

### Board routes (L68-L136)
All except `/boards/:id/public` require `requireAuth`.
- `GET /boards/:id/summary`: only `boardNumber` and `trackingNumber`, for the header's previous/next navigation.
- `GET /boards`: `ctrl.listBoards`. `?mine=true` limits the list to the caller's boards. Hidden and test-mode boards are only shown to the admin or to a frontend running on localhost.
- `POST /boards`: `ctrl.createBoard`. The service only lets the admin email create a board.
- `GET /boards/my-active-pod-boards` and `GET /boards/open-for-placement` are registered **before** `/boards/:id` on purpose. Express matches routes in registration order, so otherwise the literal segment would be cast as an ObjectId.
- `GET /boards/:id/public` (**no auth**, used by invite preview pages) and `GET /boards/:id`: `ctrl.getBoard`. That handler also promotes dugout players automatically when the protection period (PP) has expired.
- Other controller pass-throughs:
  - `movements`, `reserve-position`, `place-user`, `reservations`
  - `split` (phase-1 board split), `penciling`, `prepick`
  - `players/:id`, `promote-dugout-pp`, `hp-invite`
- Board-setup routes:
  - `GET /stats`, `GET /distributors`, `GET /users/search`
  - `POST /boards/:id/assign`, `/activate`, `/fix-dugout`
  - `/hidden`: only the admin email may use it, enforced in the controller.

### Distributor progress with self-heal (L142-L305)
`GET /distributor/progress` returns the caller's "Path to Bat246 Distributor" state:
- `isQualified`, `membershipExpiresAt`, `qualifiedAt`, `bat246RefUserId`, `invitedProductId`, `inPod` (`podPlacedPositionKey` starts with `pod-`), `isGarageAffiliate`
- `steps` = `{isOfficeMember, hasPurchasedProduct, hasBat246Membership}`, plus `completedCount` and `totalCount: 3`.

Because the boards page calls it on every load, it also repairs missed writes:
1. **`hasPurchasedProduct` false.** It looks for a paid `Invoice` whose line items include a product tagged `bat246_entry`. If one exists:
   - It upserts the distributor with `hasPurchasedProduct: true, isOfficeMember: true`.
   - It fills in `bat246RefUserId` from `resolveBat246Ref` if missing.
   - If the user becomes qualified (office member and BAT246 membership), it sets `isQualified`/`qualifiedAt`, calls `assignDistributorId` and calls `maybeCreatePlacementNotification`.
2. **`isGarageAffiliate` false.** It calls `getUserPurchase` from `unilevelPlusCommission`. An active Unilevel Plus purchase sets the flag and can also complete qualification.

Errors in either repair are logged and never fail the read. `isGarageAffiliate` no longer counts toward qualification or the step count, but it is still returned.

### Membership (L307-L383)
- `GET /membership/status`: `membershipActive`, `membershipExpiresAt`, `membershipPlan` and `nextBillingAt` from `Bat246Player`.
- `POST /membership/activate-free`: `activateFreeTrialMembership`. This is a one-time free 3-month trial that replaces the old paid membership.
- `POST /membership/checkout/create-order`: legacy paid flow. It rejects users whose membership is already active, looks up the seller user by the hardcoded `ALAN_K_EMAIL`, and calls `createInvoice`:
  - organisation `BAT246_ORG_ID`
  - line item type `bat246_membership`
  - `MEMBERSHIP_PRICE_CENTS = 2000` (USD 20)
  - It returns `invoiceId`, and the frontend then pays that invoice.

### Notifications, products, office
- `GET /notifications`, `POST /notifications/:id/read`, `POST /notifications/:id/clear`: controller pass-throughs over placement notifications.
- `GET /products`: active products of the BAT246 organisation (`BAT246_PRODUCT_ORG_ID`), used by the invite modal dropdown.
- `POST /office/join`: adds the caller to the BAT246 organisation as `stakeholder` (`$addToSet`) and returns a fresh JWT (`signJwt`) scoped to that org.

### Prospect invites and claims (L433-L631)
- `POST /office-invite` `{email, productId}`:
  - The product must be tagged `bat246_entry`.
  - Callers seated in a POD cannot invite for the $650 Board Entry; that product's ID is hardcoded.
  - It upserts `Bat246OfficeInvite` by lower-cased email, recording the inviter and product. This is the durable fallback that `resolveBat246Ref` uses for attribution.
  - It emails `bat246OfficeInviteEmailTemplate`, linking to `${FRONTEND_URL}/games/bat246/office-invite?productId=…&ref=<caller>`.
- `GET /boards/:id/my-role`: whether the caller occupies any slot on that board (`canInvite`) and which one (`homePlate`, `1stA`…`1stD`, `atBat-0`…`atBat-7`, and so on).
- `GET /my-dashboard-access`: `{hasAccess, canApprove, salesCredits, atBatFilledCount, myCardType}`.
- `GET /boards/:id/pending-placements`: unexpired, unplaced `Bat246PendingPlacement` rows, used for the AT BAT tooltip.
- `POST /claim-invite` (**no auth**) `{userId, boardId, position, ref, defaultRef, invitedProductId}`:
  - It is called after the join page's sign-in modal.
  - `boardId` and `position` must come together. `position` must be in `RESERVATION_POSITIONS` or be `"unassigned"`. With neither, it is a "boardless" office invite.
  - For a real position, it upserts an active `Bat246PositionReservation` for that board and slot, re-pointing it to this user, with a 7-day expiry.
  - It resolves the referrer with `resolveBat246Ref({explicitRef, fallbackRef, email, userId})`.
  - It upserts `Bat246Distributor` using `$setOnInsert` only, so the first touch wins. That covers `bat246RefUserId`, `bat246RefBoardId` (only for `unassigned`) and `invitedProductId`.
  - A duplicate-key error returns 409.

### Approval and placement (L633-L817)
- `GET /distributors/:userId/placement-info`: allowed for card admins (`isBat246CardAdmin(..., "distributors", "inviteandplace")`) or any 1st Base player. The target must be `isQualified`. A non-admin with `salesCredits === 2` and no card yet is in **Gold Approve** mode (`atBatOnly`). In that mode they may place their third referral in any open AT BAT slot. Calls `getPlacementInfo`.
- `DELETE /distributors/:userId`: admin only. It permanently deletes only the `Bat246Distributor` document. The user, player and existing board placements are left untouched, and there is no undo.
- `POST /distributors/:userId/approve` `{boardId, position?, toDugout?}`:
  - Allowed for admins or 1st Base players. The target must be qualified and not already approved.
  - With `toDugout`, it calls `placeUserInDugout`.
  - Otherwise it calls `placeUserFromReservation`, passing `skipGreenCard: !isAdmin`. When a non-admin approves, the approver is the referrer, so the Green Card is not given to whoever owns the slot's pair.
  - It then sets `isApproved`/`approvedAt`. For non-admins it calls `maybeAwardGoldToApprover`.
- POD flow:
  - `POST /distributors/:userId/invite-pod`: `sendPodInvite`. Every click sends an email, and first-touch attribution is enforced in the service.
  - `GET /my-active-board-membership`: `isPartOfAnyActiveBoard`.
  - `POST /distributors/:userId/place-pod` `{boardId}`: `placeUserInPod`.
- $650 Board Entry flow (the second, more open path; it ends in the same `isApproved` state):
  - `POST /distributors/:userId/invite-board`: `sendBoardInvite`.
  - `GET /distributors/:userId/board-placement-info?boardId=`: `getBoardPlacementInfoForCaller`.
  - `POST /distributors/:userId/place-on-board` `{boardId, position | toDugout}`: `placeDistributorOnBoard`.
- `GET /pod-team/:teamId`: `getPodTeamDetails`. Returns the four members of a POD team, which can span two boards; used by the "P-100X" dugout popup.

### Card history (L831-L908)
`GET /players/:playerId/card-history?cardType=` returns the player's `Bat246SalesCredit` rows, oldest first, with fields `cardType`, `earnedAt`, `boardTrackingNumber`, `referredUserId`, `referredUserName`, `position` and `cardBack`. It then adds live distributor IDs to the card back:
- It collects the player IDs of the earner, the referred player and any `stolenFrom`/`stolenBy` player.
- It maps each to its `userId` through `Bat246Player`, then to `Bat246Distributor.distributorId`.
- It writes `distributorId` into `assignedTo`, `freePosition`, `stolenFrom` and `stolenBy`.

This step is needed because the card back is a snapshot taken before the referred user may have qualified.

- **Database:**
  - Read and write: `Bat246Distributor`, `Bat246PositionReservation`, `Bat246OfficeInvite`, `User` (organisation membership).

- **Environment variables:** `FRONTEND_URL` (via `config/env`) for the office-invite link.

## Notes
- **Security:**
  - `POST /claim-invite` has no authentication and trusts `userId` from the request body. Any caller can create or re-point a position reservation for any user, and can set first-touch referral attribution for a user who has no distributor record yet.
  - `GET /boards/:id/public` returns the whole board without auth.
  - Board-setup routes (`assign`, `activate`, `fix-dugout`, `stats`, `distributors`, `users/search`) only get `requireAuth` at the router level. Check `bat246.controller.ts` and `bat246Admin.service.ts` before assuming a route is admin-only. `createBoard` and `setBoardHidden` do enforce the admin email.
- The organisation ID (`BAT246_ORG_ID` / `BAT246_PRODUCT_ORG_ID`, both the same value), the admin email (`ALAN_K_EMAIL`) and the $650 product ID are hardcoded in this file and repeated in other BAT246 files.
- `GET /players/:playerId/card-history` still has four `console.log("[card-history debug] ...")` lines that print player, user and distributor IDs on every call.
- `GET /boards/:id/pending-placements` does not validate the ObjectId, so a bad ID causes a cast error and returns 500.
- The self-heal in `distributor/progress` writes to the database during a GET.
