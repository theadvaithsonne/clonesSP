# `server/bat246/__tests__/bat246.controller.test.ts`

> Jest unit tests for the `listBoards` handler in the BAT246 controller. They cover the "my boards" vs "all boards" branching, the admin/hidden-boards flag and the response shape.

**Kind:** test · **Lines:** 207

## Purpose
These tests exercise `listBoards` from `server/bat246/controllers/bat246.controller.ts` in isolation. Every Mongoose model and service it touches is replaced with `jest.mock` stubs, so no database is needed. They document the intended contract: "My Boards" is filtered by the logged-in user's lowercased email, which is stored on each board slot, and hidden boards are only visible to the hardcoded admin (Alan K).

## How it works
- **Mocks (L8-L39):** `Bat246Player.findOne`, `User.findById`, and the `bat246.service` functions (`getBoards` and `getCompletedBoards` resolve to `[]`; the rest are bare `jest.fn()`). `bat246Split.service.splitBoardPhase1` and four `bat246Admin.service` functions are also mocked.
- **Helpers:**
  - `makeReq(query, userId)` builds `{ query, user: { userId } }`.
  - `makeRes()` returns chainable `status`/`json` mocks.
  - `mockUser(email)` makes `User.findById().select().lean()` resolve to `{ email }` or `null`.
- **Cases (`describe("listBoards")`):**
  - The user is looked up even when `mine=false` or `mine` is unset, because the admin check needs the email.
  - With no `userId`, the user lookup is skipped entirely.
  - With `mine=true` and no user found, or no `userId`, the response is `{ boards: [], completed: [] }` and the services are not called.
  - With `mine=true`, the email is lowercased before it is passed (`"TripleH@YopMail.com"` becomes `"tripleh@yopmail.com"`).
  - The admin email gets `isAdmin=true`, in both the mine and all-boards views.
  - The response is `{ boards, completed }`, using whatever the service mocks return.
  - A service rejection produces a 500 with `{ error: message }`.

## Used by
Run by Jest through `npm test` (`jest`). `jest.config.js` includes `server/bat246/__tests__` in its `roots` and uses `ts-jest`. Nothing imports this file.

## Notes
- **Probably stale.** The controller now calls `svc.getBoards(filterEmail, isAdmin, includeTest)` and `getCompletedBoards` with a third `includeTest` argument, which comes from `requestIsFromLocalFrontend(req)`. That module is not mocked; with no headers it returns `false`. Several assertions still expect two arguments, for example `toHaveBeenCalledWith(undefined, false)`. Jest compares the full argument list, so those expectations are expected to fail until they add the third argument.
- The test emails are fixtures. The admin email in the tests matches the controller's `ALAN_K_EMAIL` constant.
