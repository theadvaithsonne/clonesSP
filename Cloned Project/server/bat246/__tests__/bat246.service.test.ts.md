# `server/bat246/__tests__/bat246.service.test.ts`

> Jest unit tests for the query-building logic of `getBoards` and `getCompletedBoards` in the BAT246 service.

**Kind:** test · **Lines:** 122

## Purpose
These tests check the MongoDB filter, sort and projection that `server/bat246/services/bat246.service.ts` builds when it lists boards. The Mongoose models are mocked, so the tests inspect the arguments passed to `Bat246Board.find(...)` without a real database.

## How it works
- **Mocks (L8-L22):**
  - `Bat246Board.find` returns a chainable `mockBoardChain` (`select` → `sort` → `lean` resolving to `[]`).
  - `Bat246Player` and `Bat246Movement` are stubbed.
  - Because `lean()` returns an empty array, the service's `withPositionSummary` helper returns early and never queries reservations.
- **`getBoards` cases:**
  - With no email, the status filter is exactly `["pending", "active", "stalled", "splitting"]` and there is no `$or`.
  - With an email, `$or` has 8 clauses on the slot paths `homePlate`, `thirdBase`, `secondBaseA`, `secondBaseB`, `firstBase`, `atBat`, `dugout` and `onDeckCircle` (each `.playerEmail`), and every clause value is the plain email string.
  - `splitting` is included; `split` and `completed` are not.
  - By default `hidden: { $ne: true }` is applied; `isAdmin=true` removes it.
- **`getCompletedBoards` cases:**
  - Status is `["completed", "split"]`, with the same 8-path `$or` when an email is given.
  - Results are sorted `{ createdAt: -1 }`.
  - The projection includes `splitAt`.
- Each test reads `mock.calls[0][0]`. This works because `jest.config.js` sets `clearMocks: true`, which resets the call history between tests.

## Used by
Run by Jest through `npm test`. `jest.config.js` includes the `server/bat246/__tests__` root. Nothing imports this file.

## Notes
- The tests do not cover the newer `includeTest` parameter, which adds `mode: { $ne: "test" }` unless it is true. None of the existing assertions conflict with it.
